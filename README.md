# proactive-prompt

一个「主动巡检」型 AI 助手的例程提示词：每小时醒一次，看看用户的事和状态，能代劳的先做掉，该请示的带着方案请示，没事也给出有信息量的照看。核心是**默认有输出**、**先做事再说话**、**价值优先于表演**。

| [`reference/table-schema.md`](./reference/table-schema.md) | 巡检记录表的字段与协作机制：10 个业务字段、状态枚举与流转、三层职责、存储中立接口、在 Notion / 飞书 / Excel / JSON 里怎么落地。 |
| [`reference/state-schema.md`](./reference/state-schema.md) | state 的字段与作用：它和记录表的分工（明细账 vs 汇总账）、按类别的计数器、写入时机、丢了会怎样。 |
| [`reference/reversible-actions.md`](./reference/reversible-actions.md) | 「先做还是先问」的可逆性判据（爆炸半径分级、草稿态/生效态、类授权）。索引见主提示词的「先做事，再说话」一节。 |

> `reference/reversible-actions.md` 是通用版的**可逆行动准则**，只讲判据，不绑定任何具体平台或助手框架。使用者需结合自己的权限配置来用：它不能替你决定哪些操作被允许，**沉默不等于授权**，也不能据此越过平台的安全、发送与审批规则。

## 怎么用

1. 先看 `reference/table-schema.md`，用手上的工具建一张记录表（任意支持筛选与编辑的多维表格都行）。
2. 把 `proactive-prompt.md` 作为定时任务的系统提示词。
3. 巡检时段、时区、称呼按自己的情况写进提示词。

`proactive-prompt.md` 里不含任何个人姓名、账号或私有链接。记录的访问方式（数据库 ID、表格链接、文件路径）只放在运行环境里，表也自己建——这也是它被单独拆成一份说明的原因。

注意：记录表里**没有**「已代办」「取数时间」这两列，它们是写入约定（写进「理由」等文本）；冷却按类别记在 state 里，不靠表里的「冷却截止时间」列。详见 `reference/state-schema.md`。

## 两份存储，各管一段

| | 记录表 | state |
| --- | --- | --- |
| 存什么 | 每条建议说了什么、用户回没回 | 这类事说过几次、还该不该说 |
| 粒度 | 一条建议一行 | 一个类别一个数 |
| 谁说了算 | 待办与日志 | 冷却与降频 |
| 丢了 | 待办全丢，必须备份 | 只丢降频记忆，待办不受影响 |

一句话：**记录表是明细账，state 是汇总账。** 两边不互相替对方干活 —— state 不存单条建议，记录表不存累计数。详细分工见 `reference/state-schema.md`。

## 设计要点

- **默认有输出**：静默是例外，且要有明确条件（上下文全不可用，或所有切口都在冷却）。
- **先做事再说话**：能做可逆的半成品就先做，再简短汇报，而不是只提建议。
- **请示带默认**：需要用户拍板时给推荐默认，用户不回就走可逆的那条。
- **防刷屏**：同一具体提议连续三次完全沉默 → 该类别冷却约 24 小时（记在 state 里），冷却期内换别的切口。
- **诚实**：每类上下文标取数时间（写在「理由」这类内部文本里，不进用户消息），取不到就说不可用，不编造、不拿旧数据冒充新。
- **像人说话**：口语短句，少格式、少术语，不写成工作报告。

## 本地文件

| 文件 | 是否进 Git | 说明 |
| --- | --- | --- |
| `state.json` | 否 | 跨轮记忆：按类别的沉默/冷却、当日发送计数、活动缓存。`.gitignore` 已排除。 |
| 连接信息（库 ID、表格链接、文件路径） | 否 | 不属于仓库内容。放运行巡检的环境里——宿主工具自己的配置，或本地 `.env`，`.gitignore` 已排除。 |

丢掉 `state.json` 只会失去降频记忆，不会丢待办——待办始终以记录表里状态为「待响应」的行为准。

这个仓库只交付提示词和字段说明，不含实现代码，所以也没有配置文件模板。要连哪张表、走哪个发送出口，由你用的宿主工具决定，不在本仓库的约定范围内。
